# المعمارية

## الصورة العامة

```
┌──────────── الجهاز (جوال / متصفح / Tauri) ────────────┐        ┌───────────── Supabase ─────────────┐
│  الشاشات (React) ← تقرأ دائماً من IndexedDB           │        │ PostgreSQL + RLS                   │
│        │ كتابة                                         │ push   │  ├ مشغّلات: التدقيق، التعارض،       │
│        ▼                                              │──────▶ │  │  التحديث المتسلسل، الإشعارات     │
│  mutations: تطبيق محلي فوري + outbox مرتّب             │        │  ├ pg_cron: 7:00 الملخص، الخميس     │
│        ▲                                              │ pull   │  │  التقارير، الخميس البريد          │
│  sync: دفع ← سحب تزايدي ← شواهد حذف ← مطابقة صلاحية    │◀────── │  └ pg_net ← dispatch-push           │
│        ▲                                              │realtime│ Realtime (يحترم RLS)               │
│  Realtime: يطبّق كل تغيير على IndexedDB فوراً          │◀────── │ Storage: photos/ signatures/       │
│  Service Worker: ملفات التطبيق للعمل دون اتصال         │        │          reports/ branding/        │
└───────────────────────────────────────────────────────┘        │ Edge: render-pdf, dispatch-push,   │
                                                                 │       invite-user, weekly-email    │
                                                                 └────────────────────────────────────┘
```

**المبدأ:** الشاشات لا تنتظر الشبكة أبداً. كل قراءة تأتي من IndexedDB، وكل كتابة تُحفظ محلياً ثم تُرسل. الخادم هو المرجع، وكل صلاحية تُفرض فيه.

## العمل دون اتصال (`src/lib/sync.ts`, `src/lib/mutations.ts`)

| العنصر | كيف يعمل |
|---|---|
| الكتابة | `createRecord` و`updateRecord` و`deleteRecord` تطبّق التغيير محلياً، وتضيف عملية إلى `outbox` بترتيب ثابت، ثم تطلب مزامنة |
| دمج التعديلات | تعديل سجل لم يُرسل بعد يُدمج في عمليته المعلّقة (إدراج أو تعديل) بدل تكديس عمليات متتالية |
| الدفع | بالترتيب. الإدراج المكرر (أُرسل وانقطع الاتصال قبل الرد) يُعامل نجاحاً. ورفض RLS يعيد نسخة الخادم ولا يحذف شيئاً بصمت |
| السحب | لكل جدول `updated_at > آخر مؤشر − 5 دقائق`، والجداول بالتوازي، والسجل الذي عليه تعديل معلّق لا يُكتب فوقه |
| الحذف | يُسجَّل كل حذف في `sync_tombstones`، فيحذفه الجهاز عند عودة الاتصال |
| الصلاحية | بعد كل سحب تُطابق قائمة المشاريع المتاحة: المشروع الذي سُحبت صلاحيته يُمسح من الجهاز، والمشروع الجديد يُسحب كاملاً |
| الصور | تُضغط إلى 1600px وJPEG 82%، وتُقرأ إحداثيات GPS ووقت الالتقاط من EXIF وإلا فمن موقع الجهاز، وتُحفظ في IndexedDB، ثم تُرفع في الخلفية قبل سجلها |
| ملفات التطبيق | `scripts/build-sw.mjs` يكتب قائمة بكل الملفات المصدّرة. الصفحات تُطلب من الشبكة أولاً، والملفات الثابتة من الذاكرة أولاً |
| التخزين | `navigator.storage.persist()` يطلب ألا يمسح المتصفح بيانات لم تُزامن |

## التعارض بين الأجهزة

لكل سجل عمود `version`، والمشغّل `app.touch_row` يرفض أي تعديل يحمل إصداراً قديماً بالخطأ `P0409`. عند الرفض تُحفظ نسختي ونسخة الخادم في جدول `conflicts`، وتعرض شاشة **المزامنة** الحقول المختلفة جنباً إلى جنب، ليختار المستخدم «اعتماد تعديلي» أو «اعتماد نسخة الخادم». لا يُكتب فوق أي تعديل دون قرار.

## التحديث المتسلسل

ينفّذه الخادم داخل معاملة الحدث نفسها، فلا يعتمد على أي جهاز:

| الحدث | ما يتغير |
|---|---|
| تحديث أسبوعي (الأحدث تاريخاً) | مرحلة المشروع، وحالته، ونسبته (يدوية أو من الأوزان)، و`last_update_date` |
| قبول طلب فحص في مرحلة «قبل الصب» | اقتراح بالمرحلة التالية يظهر في صفحة المشروع، ويُنقل المشروع بعد تأكيد المهندس (`decide_stage_suggestion`) |
| مخالفة جسيمة | إشعار فوري لمدير المشروع ومدير القسم، ثم Push |
| أي تغيير | سطر في سجل التدقيق، وبث لحظي لكل شاشة يحق لصاحبها رؤيته |

> **ملاحظة تشغيلية مهمة:** كل جدول تستمع له الواجهة يجب أن يكون منشوراً في `supabase_realtime`. إذا ضمّت القناة جدولاً غير منشور، تُعلَن «مشتركة» لكنها لا تستقبل أي حدث إطلاقاً. المهاجرة 8 تضمن نشر كل الجداول.

## تقارير PDF (`supabase/functions/_shared/pdf/`)

- **`rtl.ts`:** خوارزمية Unicode Bidi (bidi-js) تقسم كل سطر إلى مقاطع بترتيبها المرئي، وتقلب الأقواس في المقاطع العربية. fontkit يشكّل الحروف ويصلها ويعكس المقطع العربي. الأرقام والرموز اللاتينية (SBC 304) تبقى من اليسار لليمين.
- **ثلاث مشكلات حُلّت:**
  - تقسيم الخط جزئياً (subset) في pdf-lib يُسقط أشكال الحروف الموصولة، فيُضمَّن الخط كاملاً.
  - ميزة `calt` في الخط تختار بدائل تحتاج إزاحات GPOS لا يطبّقها pdf-lib، فعُطّلت.
  - Deno يعطّل `__proto__` الذي يعتمد عليه fontkit، فأُضيف `proto-shim.ts`.
- **`doc.ts`:** ترويسة بالشعار، وترقيم «صفحة س من ص»، وجداول تلتف خلاياها ويتكرر رأسها في كل صفحة، وشبكة صور.
- **`templates.ts`:** التقرير الأسبوعي (لقطة السبت إلى الجمعة) ومحضر الاجتماع.
- **`render-pdf`:** يقرأ السجل بصلاحيات المستخدم (RLS)، ويحفظ الملف في حاوية `reports`، ويعيد رابطاً مؤقتاً لعشر دقائق.

## الإشعارات

```
notifications (INSERT) ──مشغّل pg_net──▶ dispatch-push ──▶ Web Push / FCM / APNs
        ▲                                      ▲
        └── pg_cron كل دقيقة (احتياط) ─────────┘   claim_unpushed_notifications يحجز الدفعة ذرّياً
```

- **منع التكرار:** `dedupe_key` فريد لكل مستخدم.
- **الاشتراكات المنتهية:** حين ترد القناة بأن الجهاز لم يعد مسجّلاً (404/410)، يُحذف اشتراكه.
- **الملخص اليومي:** في الساعة 7:00 بتوقيت الرياض، إشعار واحد لكل مستخدم يقتصر على مشاريعه.
